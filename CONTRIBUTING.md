# Contributing

## What this repository is

The source of the Sunstone extension, published so that the claims in
[SECURITY.md](SECURITY.md) can be checked rather than taken on trust. The measurement harness, the
benchmark sets and the roadmap are developed elsewhere and are not here.

The licence is [BUSL-1.1](LICENSE). It is source-available rather than open source. Read it before
you build something on top of this.

## Before you open a pull request

Small fixes are welcome without ceremony. For anything larger, open an issue first and say what you
intend. A change that alters what leaves the machine, how a key is stored, or what the page server
is bound to needs to be discussed before it is written, because those are the properties the
product is sold on.

## Building

```
npm install
npm run typecheck    # tsc --noEmit
npm run build        # esbuild bundle to out/
```

`media/` is not in this repository. It is the Black Window engine, generated by
`scripts/sync-engine.sh` from a separate source, with the commit it came from recorded in
`media/ENGINE_COMMIT`. You can typecheck and build without it. Packaging and running the extension
need it, so a clone of this repository alone cannot produce a working `.vsix`. If you need one to
work against, ask.

Never edit `media/` by hand. A change there is lost on the next sync.

## Things that are easy to get wrong

These are the ones that have bitten us, recorded so they bite you less.

- **Keys.** A place's key lives in `SecretStorage` under `sunstone.key:<url>`. Not in settings, not
  in the page's storage, not on a command line, not in a log line.
- **Persistence.** The weave is saved as one re-serialized JSON blob. `save()` writes a temp file
  and renames over the live one; `restore()` moves an unreadable store aside rather than saving
  over it, because notes, lookups and digests have no source file to rebuild from. Keep both
  properties in any change to persistence.
- **Conversation sources.** Sources under `chat:` and `tool:` belong to an open conversation, not
  to the store. They are filtered out of `save()` and out of the default `search()` excludes. A
  change that persists them grows the store without bound and puts one chat's turns into every
  later search result.
- **The page's origin.** See SECURITY.md. `127.0.0.1` is load-bearing.
- **`.vscodeignore` is an allowlist,** not a denylist. Everything is excluded and a few things are
  named back in. That is deliberate: the denylist that stood there once shipped assessment
  artifacts carrying absolute home paths into a published package. If your change adds a directory
  that must ship, name it in both `.vscodeignore` and `scripts/check-vsix.sh`, which fails the
  build on anything it was not told about.

## Style

Full sentences in comments and commit messages, leading with the fact. Write a comment to say what
the code cannot say for itself, usually why rather than what. Measured numbers rather than
adjectives.
